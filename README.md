# nvate — свадебные онлайн-приглашения

Telegram-бот, Studio и сервер приглашений. Пара собирает персональное приглашение, администратор подтверждает оплату, а платформа публикует чистую ссылку вида `/ali-and-zebo` и, при необходимости, именные гостевые ссылки.

## Что работает

- **Восемь публичных дизайнов в разных стилях.** Ночные: **Oqshom** (изумрудный вечер), **Nafis** (винный бархат), **Gulzor** (ночной сад с листопадом), **Shirin** (догорающий закат), **Deco** (ар-деко: золотые лучи веером). Светлые: **Nur** (утренние лучи и пыль в них), **Marvarid** (жемчужный перламутр), **Charos** (белый мрамор и золотые арки). У каждого своя палитра, свои шрифты и собственный слой эффектов; общими остаются отделка (стеклянные карточки, золотая типографика) и сцена открытия.
- **Конверт с анимацией открытия — у всех восьми.** Он нарисован, а не снят: бумага, подкладка, диагональные швы и сургучная печать собраны из градиентов, поэтому принимают цвет темы. Открытие идёт в четыре такта — печать откалывается, клапан откидывается назад, письмо с именами выезжает, камера наезжает на бумагу и передаёт кадр странице (около пяти секунд).
- RU/UZ Studio: одна вертикальная нить из девяти шагов, живое звёздное небо на canvas, стекло в духе последних iOS, свет и фон меняются от блока к блоку. Появление блока — 0,5 с, переходы между шагами — медленные и плавные.
- Точный production-preview через `/api/preview`, живые превью шаблонов прямо в карусели (анимация идёт только в карточке в фокусе).
- Telegram Web App authentication, идемпотентная отправка заявки (`submissionKey`), защищённые чеки об оплате.
- **Справочник тойхон и своя карта.** Тойхоны Мангита не размечены ни в Яндексе, ни в Google — искать их на общей карте бесполезно. Шаг «Где» показывает поиск, под ним карту города со всеми местами каталога и список карточек: тап по метке или карточке ставит точку и подставляет название. Карта своя (`public/app/map.js`) — чужие виджеты приносили линейку, компас и «моё местоположение», которые убрать нельзя; здесь на карте ровно две кнопки, плюс и минус. Админ добавляет тойхону тапом по той же карте. См. `catalog/README.md`.
- **Музыка — YouTube и своя, прямо в форме.** В шаге «Musiqa» сразу два источника, без окон: **YouTube** (поиск; «Tinglash» только включает песню, выбирает её «Tanlash»; пока строка пуста — «Топ nVate»: песни, которые пары чаще всего ставят в приглашения, личные файлы в топ не попадают, `src/musicTop.js`) и **Mening musiqam** — всё своё: **magic import** по ссылке (YouTube, TikTok, Instagram, Facebook, VK и др. — звук извлекает сервер), загрузка аудио или видео (из видео звук достаёт ffmpeg) и песни, присланные боту (аудио, голосовые, видео, кружки и ссылки текстом). Любой выбор ведёт на «катушку» — выбор начала: волна песни лентой под золотой иглой, ленту тянут пальцем и бросают, касание подвозит момент к игле, снизу — вся песня с окошком видимого куска, «Top tanlov» и «Shu yerdan tinglash». Кнопки «сохранить» нет: песня и начало ложатся в черновик сами, а после каждого сдвига песня звучит пять секунд и плавно гаснет; сверху — «O‘zgartirish», чтобы выбрать другую. Ролик из поиска YouTube сервер тоже пробует скачать: получилось — у катушки настоящая волна, а в приглашении файл; YouTube не отдал — песня играет официальным IFrame-плеером. Архитектура: `src/extract.js` (yt-dlp и ffmpeg, отсечение внутренних адресов), `src/musicImport.js` (очередь задач, одно и то же дважды не качает), источники за фасадом `src/musicProviders.js`, студия — `public/app/music-core.js` (одно состояние шага), `music-player.js` (единый плеер), `music-start.js` (катушка), `music.js` (раздел).
- **Уже оформленные приглашения** с песнями библиотеки nVate и Audius продолжают играть: адрес звука `/api/music/audio/<источник>/<id>`, файлы библиотеки — в uploads или Cloudflare R2 / S3 (`src/objectStore.js`, подпись SigV4 на сервере). В студии и в админке этих источников больше нет.
- **В приглашении** песня стартует с выбранной секунды (`#t=` и `currentTime` для звука, `startSeconds`/`seekTo` для YouTube), доигрывает до конца и мягко возвращается к отметке. Если браузер не дал включить звук сам, кнопка музыки зовёт коснуться страницы; удалённая или закрытая песня молча убирает кнопку. Старые приглашения (загруженный файл, ссылка YouTube, iTunes, прямой mp3) играют как раньше.
- **Готовое приглашение в боте.** После оплаты пара получает по порядку: карточку с уникальным QR-кодом в рамке nvate.uz (`src/share.js`, рамка — `public/assets/share/qr-frame.png`), общую ссылку с многоразовой кнопкой «Поделиться» и именные ссылки с одноразовыми кнопками «Отправить», которые исчезают после отправки. Кнопки работают через инлайн-режим бота: включите его в @BotFather командой `/setinline`. Без него кнопки открывают обычное окно «поделиться» и не исчезают.
- **Главный адрес — nvate.uz** (`BASE_URL`). Страницы на `*.up.railway.app` постоянным редиректом переезжают на него; `/health` и API не трогаются.
- **Админ-панель** (`/admin`) с четырьмя вкладками: показатели, заявки, цены и тойхоны. Тойхона добавляется тапом по карте: нажали «Добавить», ткнули в место, подписали, подтвердили — координаты руками не вводятся. Из неё можно подтвердить оплату (паре уходит ссылка тем же сообщением, что и из бота), отклонить заявку, посмотреть чек и контакты, а также менять цены — каждого шаблона, именной ссылки и допфункций. Пустое поле возвращает заводскую цену из `manifest.json`; уже оформленные заказы сохраняют свою сумму.
- SQLite-заявки, персональные slug-и и именные гостевые ссылки; неизвестный гостевой slug показывает общее приглашение, а не 404.
- Скрытый legacy-рендер **Atlas** — новым клиентам не показывается, но оплаченные ссылки на нём продолжают открываться.

## Запуск

Нужен Node.js 24. В production используется PostgreSQL через `DATABASE_URL`; без неё локально работает SQLite.

```powershell
npm install
Copy-Item .env.example .env
npm start
```

Для локальной проверки без Telegram установите `DEV_NO_AUTH=1` и откройте `http://localhost:3000/app/`. Никогда не включайте этот флаг в production.

Стенды и автотесты, где браузер всегда сообщает `prefers-reduced-motion: reduce`, можно смотреть в движении: `document.documentElement.dataset.motion = 'full'` включает анимации принудительно (на живых пользователей это не влияет).

## Проверка

```powershell
npm test
npm audit --omit=dev
```

Тесты используют отдельную временную SQLite-базу через `NVATE_DATA_DIR` и не изменяют рабочую `data/wedding.db`. Для проверки PostgreSQL задайте `NVATE_TEST_DATABASE_URL` на отдельную пустую тестовую базу; тесты сохраняют в ней свои записи. Рабочую базу для тестов использовать нельзя.

## PostgreSQL на Railway

Сервис `wedding-app` использует `DATABASE_URL=${{nvate-postgres.DATABASE_URL}}` по внутренней сети. При отсутствии URL на Railway запуск останавливается, чтобы случайно не создать пустую SQLite-базу. `/health` проверяет реальное соединение с базой; Railway направляет трафик только после успешной проверки.

Фотографии, музыка и чеки остаются файлами: постоянный volume монтируется в `/data`, а `NVATE_DATA_DIR=/data`. Volume обязателен для сохранения загрузок между деплоями.

При первом переносе остановите запись в старое приложение, сохраните согласованную копию SQLite и каталог `uploads`. Восстановите их на volume и задайте `NVATE_MIGRATE_SQLITE=/data/wedding.db`. Импорт выполняется одной транзакцией в пустую PostgreSQL-базу, сохраняет ID, ссылки, даты и настройки, проверяет количество записей и обновляет последовательности ID. Метка миграции предотвращает повторный импорт; исходная SQLite-база не удаляется. После проверки уберите `NVATE_MIGRATE_SQLITE`. После появления новых записей в PostgreSQL старая SQLite-копия уже не подходит для простого отката.

## Настройка

Основные переменные перечислены в `.env.example`:

- `BOT_TOKEN`, `BOT_USERNAME` — Telegram-бот;
- `ADMIN_CHAT_IDS` — один или несколько Telegram chat ID через запятую;
- `BASE_URL` — публичный HTTPS origin;
- `MAP_TILES` — шаблон адреса тайлов карты (`{z}/{x}/{y}`). По умолчанию OpenStreetMap: ключей не просит, но нагрузку держит на добром слове — под заметный трафик поставьте своего провайдера;
- `GOOGLE_MAPS_API_KEY` — необязательный ключ для поиска мест вне каталога;
- `SUPPORT_URL` — ссылка поддержки;
- `YOUTUBE_API_KEY` — необязательный ключ YouTube Data API v3 для поиска песен (без него — страница выдачи youtube.com);
- `YTDLP_BIN`, `FFMPEG_BIN` — пути к yt-dlp и ffmpeg для magic import (в Docker-образе уже есть); `YTDLP_PROXY`, `YTDLP_COOKIES` — если YouTube просит сервер «подтвердить, что вы не бот»: резидентный прокси и/или cookies в формате Netscape (путь, текст или base64); `YTDLP_JS_RUNTIME` — JS-движок для роликов YouTube (по умолчанию `node`);
- `MUSIC_STORAGE`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_PUBLIC_URL`, `S3_URL_TTL` — хранилище песен библиотеки nVate, уже выбранных в приглашениях. По умолчанию `local` (uploads на volume); для Cloudflare R2 — `MUSIC_STORAGE=s3`, endpoint `https://<account-id>.r2.cloudflarestorage.com`, регион `auto`. Ключи живут только на сервере;
- `AUDIUS_API_URL`, `AUDIUS_APP_NAME` — необязательные настройки публичного API Audius для старых приглашений (ключ не нужен).

Telegram Web App требует HTTPS. Для локальной интеграции можно использовать HTTPS-туннель и указать его origin в `BASE_URL`.

## Архитектура

```text
src/
  index.js          запуск HTTP-сервера и Telegram-бота
  server.js         маршруты Studio, preview, upload, admin и приглашений
  service.js        валидация, заявки, оплата, slug-и и гостевые ссылки
  render.js         production/demo renderer и локализация данных
  experience.js     открытие приглашения, живой фон и звёздное поле
  theme.js          ядро оформления приглашений: типографика, моушн, стекло, золото
  design.js         границы оформления заказа (палитра, свет, эффект) и канцелярия тем
  templateStore.js  публичный каталог и hidden legacy renderers
  db.js             асинхронные операции с заявками и настройками
  storage.js        PostgreSQL/SQLite, транзакции и перенос данных
  schema.js         схема и совместимые миграции
  pricing.js        цены: заводские из manifest/config + переопределения админа
  venues.js         справочник тойхон: семя из catalog/ + правки админа в settings
  musicProviders.js источники музыки за одним фасадом: в студии YouTube и своя музыка
  musicLibrary.js   библиотека nVate: песни, которые ещё играют в оформленных приглашениях
  musicSelection.js выбранная песня: проверка, сведения из источника, звук в приглашении
  objectStore.js    файлы библиотеки: uploads или Cloudflare R2 / S3 (подпись SigV4)
  audius.js         поток Audius для оформленных приглашений
  music.js          своя музыка пары: песни из бота, загруженные и импортированные
  extract.js        звук из ссылки (yt-dlp) и из видео (ffmpeg), защита от внутренних адресов
  musicImport.js    задачи импорта: очередь, прогресс, повторно одно и то же не качает
  youtube.js        поиск песен (только встраиваемые), их имена и «Топ выбор»
templates/
  oqshom|nafis|nur|gulzor|
  marvarid|charos|shirin|deco/      восемь публичных дизайнов
  atlas/                            скрытый рендер для старых оплаченных ссылок
catalog/
  venues.json       стартовый список тойхон (см. catalog/README.md)
public/app/          Studio без build-step (app.js, sky.js — звёздное небо,
                     map.js/map.css — своя карта на тайлах, style.css)
public/admin/        админ-панель
data/                рабочая БД, uploads и backups
test/                изолированные интеграционные тесты
```

Папка нового renderer-а содержит `manifest.json` и `template.html`. `listed: true` публикует дизайн для новых заказов; `listed: false` оставляет его только для совместимости. Не удаляйте hidden renderer, пока его ID встречается в базе. Неизвестный ID намеренно завершает рендер ошибкой — платформа никогда не подменяет приглашение другим дизайном.

Общий слой отделки живёт в `src/theme.js` (`coreCSS`) и `src/experience.js`: конверт, звёздное поле (`starfield`), золотая пыль, класс `.glass` и золотая типографика `.gilt` — один рецепт на все восемь дизайнов, поэтому новая тема стоит палитры и своего слоя эффектов, а не пятисот строк. Цвета конверта тема задаёт в таблице `ENVELOPES` (`src/experience.js`), описание для каталога — в `STATIONERY` (`src/design.js`).

Витрина шаблонов в студии держит живыми только три превью (текущее и соседей), а тяжёлые фоновые слои в режиме карточки выключены — иначе восемь одновременно работающих приглашений кладут даже настольный браузер.

Design brief, IA, токены, задачи и контрольные скриншоты лежат в `.design/`.
